# 🔌 «Via автоматизация» — Руководство по интеграции с B2B CRM и Сервис-Десками

Промышленная платформа **«Via автоматизация» (Via Automation)** предназначена для автоматизации службы технической поддержки и модерации в игровых проектах, мобильных приложениях и онлайн-сервисах.

Платформа работает как **умный автономный авто-ответчик (Deflection Engine)**:
1. Принимает входящие обращения из любой CRM / Service Desk.
2. Мгновенно классифицирует запрос, проверяет базу знаний и регламенты (RAG).
3. **Автономно отвечает клиенту/игроку (Auto-Reply)**, если обращение типовое, а уверенность ИИ выше заданного порога.
4. **Безопасно эскалирует человеку (Human-in-the-Loop)**, если требуется решение модератора или жалоба нестандартная, прикрепляя к тикету готовый черновик ответа и ссылки на пункты правил.

## 🤖 1. Подключение Telegram Support Bot

Telegram — наиболее популярный канал связи с игроками и комьюнити. «Via автоматизация» позволяет боту мгновенно отвечать на вопросы игроков 24/7.

### Шаг 1: Получение токена бота
1. Откройте диалог с официальным ботом [@BotFather](https://t.me/BotFather) в Telegram.
2. Создайте нового бота (`/newbot`) или скопируйте токен существующего.

### Шаг 2: Создание закрытой группы для эскалаций
1. Создайте группу в Telegram для ваших модераторов/операторов (например, *«Grand Support Escalations»*).
2. Добавьте в нее вашего бота и сделайте его администратором.
3. Узнайте `chat_id` группы (например, с помощью бота `@userinfobot` или через метод `getUpdates`). `chat_id` группы обычно начинается с минуса (например, `-100192837465`).

### Шаг 3: Настройка вебхука
Зарегистрируйте вебхук на сервере «Via автоматизация»:
```bash
curl -X POST "https://api.telegram.org/bot<ВАШ_BOT_TOKEN>/setWebhook" \
     -d "url=https://<ВАШ_ДОМЕН_ИЛИ_IP>:8000/webhook/telegram"
```

### Шаг 4: Указание параметров в Admin Panel
Откройте вкладку **«🔌 CRM & Авто-ответчик»** в панели администратора (`http://localhost:8501`), перейдите на подвкладку **«Telegram Support Bot»** и сохраните:
- `Telegram Bot Token`
- `ID закрытого канала операторов (chat_id)`

**Результат:** Когда игрок пишет боту вопрос (*"Как устроиться на работу инкассатором?"*), бот отвечает прямо в чат за 0.05 секунды. Если игрок жалуется на бан администратора, бот отправляет вежливое уведомление о проверке, а операторам в закрытую группу падает алерт с черновиком решения!

## 🎫 2. Подключение Zendesk Helpdesk

Интеграция с Zendesk позволяет автоматизировать работу глобального саппорта: типовые тикеты закрываются сами, а сложные снабжаются черновиком ответа.

### Настройка в Zendesk Admin Center:
1. Перейдите в **Admin Center** -> **Apps and integrations** -> **Webhooks**.
2. Создайте Webhook:
   - **Name:** `Via Automation Auto-Reply Engine`
   - **Endpoint URL:** `https://<ВАШ_ДОМЕН_ИЛИ_IP>:8000/webhook/zendesk`
   - **Request Method:** `POST`
   - **Request Format:** `JSON`
3. Создайте **Триггер (Trigger)**:
   - **Conditions:** `Ticket is Created`
   - **Actions:** `Notify active webhook` -> выберите созданный вебхук.
   - **JSON Body:**
```json
{
  "ticket": {
    "id": "{{ticket.id}}",
    "subject": "{{ticket.title}}",
    "description": "{{ticket.description}}",
    "requester_id": "{{ticket.requester.id}}",
    "tags": ["{{ticket.tags}}"]
  }
}
```

### Как это работает в Zendesk:
- **Авто-ответ:** Система вызывает Zendesk API `PUT /api/v2/tickets/{id}.json`, добавляя публичный ответ `{"comment": {"body": "...", "public": true}, "status": "solved"}` и тег `via-auto-replied`.
- **Эскалация:** Система оставляет **приватную внутреннюю заметку (Internal Note)**, видимую только агентам саппорта:
  > 🛡️ *[VIA AUTOMATION] Тикет требует внимания человека. Категория: complaint.admin | Приоритет: P1.*
  > 💡 *Рекомендованный черновик ответа: Здравствуйте! Ваша жалоба на администратора...*
  > *Статьи правил: 1.1, 1.4.*

## 💼 3. Подключение amoCRM и Bitrix24

### amoCRM:
1. Перейдите в **amoCRM** -> **Настройки** -> **Интеграции** -> **Webhooks**.
2. Добавьте Webhook на событие *"Создание сделки"* или *"Входящее сообщение"*.
3. URL вебхука: `https://<ВАШ_ДОМЕН_ИЛИ_IP>:8000/webhook/crm/ticket`.

### Bitrix24:
1. В левом меню выберите **Разработчикам** -> **Другое** -> **Исходящий вебхук**.
2. В поле **URL вашего обработчика** укажите: `https://<ВАШ_ДОМЕН_ИЛИ_IP>:8000/webhook/crm/ticket`.
3. Выберите событие: `ONCRMDEALADD` или `ONIMCONNECTORMESSAGEADD`.

## ⚡ 4. Универсальный REST Webhook API (для любых систем)

Если у вашей компании самописный Helpdesk, мобильное приложение или игровой клиент, используйте прямой REST API.

### Эндпоинт:
```http
POST https://<host>:8000/webhook/crm/ticket
Content-Type: application/json
```

### Пример запроса (Входящий тикет):
```json
{
  "ticket_id": "TICKET-98214",
  "text": "Здравствуйте, подскажите, со скольки лет можно вступить в Армию на сервере?",
  "user_id": "player_id_7781",
  "lang": "ru",
  "callback_url": "https://my-game.com/api/v1/support/callback",
  "attachments_count": 0
}
```

### Пример ответа при Авто-ответе (AUTO_REPLIED):
```json
{
  "ticket_id": "TICKET-98214",
  "action": "AUTO_REPLIED",
  "auto_replied": true,
  "reply_sent": "Здравствуйте! Вступление в ряды Армии доступно игрокам со 2-го уровня персонажа и при наличии медицинской карты.",
  "triage": {
    "category": "report.question",
    "priority": "p3",
    "confidence": 0.89,
    "needs_human": false
  },
  "audit_timestamp": "2026-11-09T14:48:10.123456"
}
```

### Что отправляется на ваш `callback_url`:
Система делает асинхронный HTTP POST на ваш сервер:
```json
{
  "event": "ticket.auto_replied",
  "ticket_id": "TICKET-98214",
  "status": "resolved",
  "reply_text": "Здравствуйте! Вступление в ряды Армии доступно игрокам...",
  "timestamp": "2026-11-09T14:48:10.123456"
}
```

## 🛡️ 5. Политика безопасности и Guardrails

Авто-ответчик платформы «Via автоматизация» оснащен тремя уровнями защиты:
1. **Никаких галлюцинаций правил:** Модель цитирует только реальные статьи из регламента `rules.json`. При попытке выдумать несуществующий пункт срабатывает Guardrail-санитайзер.
2. **Защита от обещаний разбана и компенсаций:** Модели запрещено давать обещания разблокировки, выдачи валюты или доната без прямого решения администратора.
3. **Белый список категорий для автопилота:** По умолчанию авто-ответ разрешен только для безопасных тем:
   - `report.question` (Вопросы по игровому процессу и модулям)
   - `report.help` (Просьбы о помощи)
   - `report.offtopic` (Оффтоп и приветствия)
   - `complaint.invalid` (Жалобы без доказательств)
4. **Обязательная эскалация:** Темы с подозрением на взлом аккаунта (`report.account`), проблемы с донатом (`report.payment`), жалобы на администраторов (`complaint.admin`) и подозрения в читерстве (`complaint.cheat`) **никогда не закрываются роботом** и всегда эскалируются с приоритетами `P0` / `P1`.

## 📊 6. Бизнес-показатели и Deflection Rate

Система непрерывно рассчитывает экономический эффект автоматизации:

$$\text{Deflection Rate} = \frac{\text{Количество авто-ответов}}{\text{Общее число входящих тикетов}} \times 100\%$$

$$\text{Сэкономленные часы операторов} = \frac{\text{Количество авто-ответов} \times 3.0 \text{ мин}}{60 \text{ мин}}$$

Все показатели доступны в реальном времени через эндпоинт `GET /crm/metrics` и отображаются на главном экране панели администратора.
